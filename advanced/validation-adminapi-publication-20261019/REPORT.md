# Published Advanced Admin API and application regression

Validated on 19 October 2026 in `ops-advanced-security-lab` (guest
`ops-advanced-lab`), single-node K3s `v1.37.1+k3s1`, `linux/amd64`.

## Publication and source references

- Admin API: `miki3421/openserverless-admin-api:advanced`, commit
  `74d0727d4cb25302d123d7de0af33857349a012b`. This adds only the personal
  publishing workflow to the previously tested API source `e96f790`.
- Published image:
  `ghcr.io/miki3421/openserverless-admin-api@sha256:cb8af61e8ab240907879556e04fae9350193966406ab1352ed0efc4174f013df`.
- Traceable source tag: `advanced-74d0727d4cb25302d123d7de0af33857349a012b`.
- [Successful Actions run](https://github.com/miki3421/openserverless-admin-api/actions/runs/39216487572).
- Task catalog: `miki3421/openserverless-task-custom:advanced`, commit
  `d5f3dac`, pins `config.images.systemapi` to the published manifest digest.

The workflow triggers only for relevant pushes to the personal `advanced`
branch, has an explicit repository guard, and grants package write access to
its job. It authenticates to GHCR with the temporary Actions token. It neither
creates Git tags/releases nor uses Apache publication credentials or targets.
Nine builder security unit tests ran in the built image before publication.

The registry manifest was fetched anonymously, and its SHA-256 was independently
checked against the digest header and push log. K3s pulled the image directly
from GHCR without an image pull secret. The installed Pod reports the same
manifest digest and is Ready. No local Docker image import was used for this
validation. `publication.json`, `manifest.json` and `deployment.json` preserve
this evidence. The publication currently supports `linux/amd64` only.

## Builder and application tests

The test used an explicit copy of the personal Advanced tasks at
`/home/ubuntu/ops-advanced-current/oplugins`. Existing builder receipts were
preserved under a backup directory, so both first deployments required fresh
build Jobs.

- Beta Node.js: automatic build, monitored push, deploy and invocation PASS;
  `is-number` 7.0.0 resolves from `/opt/ops-deps/node_modules`.
- Beta Python: automatic build, monitored push, deploy and invocation PASS;
  `humanize` 4.13.0, `Faker` 30.8.2 and the extension hook are present.
- Repeated deployments of both actions reused successful tenant-owned build
  receipts. Source code and dependency manifests were not edited.
- Both successful Jobs preserve `hostUsers: false`,
  `automountServiceAccountToken: false`, `privileged: false`, ownership labels
  and the resulting image annotation.
- Builder authorization: anonymous status returns 401, Alpha querying Beta's
  Job returns 404, Beta querying its own Job returns 200 with only
  `job_name/state/image`, and Alpha targeting Beta's image returns 400.
- Alpha/Beta HTTP suite: all 12 checks PASS, including synthetic writes and
  persistence reads across PostgreSQL, MongoDB, Redis, S3 and Milvus, anonymous
  and invalid credentials, peer credentials, and rejected tenant override input.
- Hashes of all 144 selected Alpha/Beta package and web files match before and
  after the run. Archives, generated bytecode and dependency directories were
  excluded; application source and manifests were included.

The accompanying JSON files contain sanitized test results and source hashes.
Private deployment/login logs and credentials were not published. This is a
regression check for the published artifact, not a new independent security
review or a complete cluster acceptance run. The comparative baseline VM was
not changed.
